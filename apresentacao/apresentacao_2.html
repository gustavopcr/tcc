Contexto

  • Base dos computadores modernos: Arquitetura Von Neumann.
  • Conceito de Programa Armazenado: Instruções e dados são representados da mesma forma.
  • Execução Sequencial: Controle de fluxo através do registrador Program Counter (PC).
3 / 22

Contexto

  • Pipelining: Técnica de sobreposição para aumentar vazão de instruções.
  • Previsão de Desvio: Especulação do fluxo de controle para evitar paradas na CPU.
  • Execução Fora de Ordem: Processamento dinâmico baseado na disponibilidade de dados, não apenas na sequência do código.
  • Superescalar: Capacidade de buscar, decodificar, executar e despachar várias instruções simultaneamente

Gargalo de Von Neumann

  • Acesso a memória é ordens de magnitude mais lento do que processamento
  • Uso de caches ajuda a mitigar a latência mas não resolve o problema por completo

Problema

  • Lei de Moore: Desaceleração severa.
  • Fim da escala de Dennard: Ao reduzir o tamanho dos transistores, a densidade da potência se mantém constante.

Trabalhos Relacionados

  • Profiling a Warehouse-scale computer:
    • Profiling realizado pela Google em seus datacenters, analisando vários tipos de carga.
    • CPU permanece grande parte do tempo em bolhas, 50% - 60% do tempo esperando dados.
12 / 22

Trabalhos Relacionados

  • Google TPU v1 (Jouppi et al., ISCA 2017)
    • Systolic Arrays:TPU utiliza uma malha de ALUs onde os dados fluem, maximizando a reutilização sem acessos intermediários à memória.
    • Eficiência Energética: Remove caches genéricos e lógica de controle complexa para dedicar área do silício massivamente à aritmética, atingindo 30x-80x mais eficiência (TOPS/Watt).

  • Samsung HBM-PIM (Kwon et al., ISSCC 2021)
    • Abordagem Near-Data: Ataca o Memory Wall integrando unidades de processamento diretamente dentro dos bancos de memória, reduzindo a movimentação de dados e o consumo energético em ~70%.
13 / 22

Proposta - Dataflow

  • Arquitetura orientada a dados ao invés de instruções.
  • Nós são disparados quando todos os operandos estão disponíveis.
14 / 22

Dataflow - Pontos Fortes

  • Tolerância a latência
  • Sincronização implícita
  • Alto grau de paralelismo.
15 / 22

Dataflow - Pontos Fracos

  • Explosão de paralelismo.
  • Falta de ferramental.
  • Falta de mecanismo para interrupção.
  • Alto overhead em comunicação

Comparativo: Long Input

Métrica Von Neumann Dataflow (Proposto)

IPC 0.98 3.72

Destaque: Enquanto o MIPS sofre com 50 ciclos de Stalls (espera), o Dataflow mantém as unidades ocupadas, atingindo um IPC quase 4x maior.

Conclusão

  • Resultados Expressivos: A arquitetura Dataflow se mostra promissora para cargas orientadas a dados, prioriazando vazão máxima ao invés de latência minima.
  • Acelerador de Hardware Dataflow vem não como substituto para a CPU, mas como um complemento para cargas de trabalho específicas.

  • Limitações:
    • A emulação não é totalmente fiel mas possibilita explorar ideias

  • Trabalhos Futuros:
    • Utilizar de FPGAs para criação de um processador Dataflow
    • Validar algortimos de maior escala
